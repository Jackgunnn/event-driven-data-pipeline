# Event-Driven Data Pipeline

A personal data engineering project for building a reusable, event-driven data platform.

The long-term goal is to create a data pipeline that can receive events from applications such as Discuzz(My QnA forum app) and process them using Kafka, PySpark, cloud storage, and Airflow.

## Current Architecture

```text
Event Simulator
      ↓
Kafka Producer
      ↓
Kafka Topic
      ↓
PySpark
      ↓
Data Lake / S3
      ↓
Airflow
```

> **Current status:** Kafka infrastructure and event simulation are complete. Python → Kafka integration is the next milestone.

# Phase 0 — Proof of Concept

The first objective is to prove that application events can flow through Kafka before adding Spark, S3, and Airflow.

## 1. Event Simulator

Created `event_simulator.py` to generate Discuzz-style application events.

Supported events include:

```text
question_posted
answer_posted
question_upvoted
answer_upvoted
question_downvoted
answer_downvoted
question_deleted
answer_deleted
question_edited
answer_edited
```

Each event contains common metadata such as:

```json
{
  "event_id": "UUID",
  "event_version": 1,
  "event_type": "question_posted",
  "source": "quora-clone",
  "user_id": "UUID",
  "timestamp": "UTC timestamp"
}
```

Additional fields such as `question_id` and `answer_id` are generated depending on the event type.

The simulator is intentionally simple. Its purpose is to provide a source of events for the data pipeline rather than become a project by itself.

# 3. Kafka KRaft Setup

Kafka was configured using **KRaft mode**, which allows Kafka to run without ZooKeeper.

A cluster ID was generated using:

```bash
kafka-storage.sh random-uuid
```

The Kafka storage was initialized in standalone mode:

```bash
kafka-storage.sh format \
  -t <CLUSTER_ID> \
  -c /opt/kafka/config/server.properties \
  --standalone
```

This is a single-node local development setup.

# Kafka Concepts Learned

### Topic

A topic is a logical stream/category of Kafka records.

In this project:

```text
discuzz_events
```

contains events generated by the Discuzz application.

### Record / Event

A record is an individual message stored in a Kafka topic.

Example:

```json
{
  "event_type": "question_posted",
  "user_id": "123",
  "question_id": "456"
}
```

### Partition

A topic is divided into partitions. Records are stored inside partitions.

Conceptually:

```text
discuzz_events
└── Partition 0
      ├── Offset 0 → hello kafka
      ├── Offset 1 → question_posted
      ├── Offset 2 → answer_posted
      └── Offset 3 → question_upvoted
```

### Offset

Each record within a partition receives an offset.

Offsets allow Kafka consumers to track their position in the stream.

## Project Philosophy

This project is being built incrementally.

The approach is:

1. Build a working component.
2. Verify it independently.
3. Connect the next component.
4. Learn concepts when they become necessary.
5. Improve the system as new requirements appear.

The final objective is  to build a reusable data platform that can eventually consume real events from personal applications.
